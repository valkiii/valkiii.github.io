Block A · What is an agent?

What is an agent?

Strip away the hype: an agent is software that perceives something, decides what it means, and acts — on its own, in a loop — instead of waiting for you to do each step by hand.

🌡️ A thermostat

Perceives the room's temperature, decides it's too cold, acts by turning on the heat. No AI involved — the simplest possible agent.

🧹 A robot vacuum

Perceives a wall through a bump sensor, decides to turn, acts by changing direction. Still just a loop.

📚 Today's build

Perceives a new article, decides — using a language model's judgment — whether it matches your interest, acts by adding it to your book.

Speaker note The point of this slide: "agent" isn't a new idea invented for AI — thermostats and Roombas have been agents for decades. What's new is using a language model for the "decide" step, so it can handle judgment calls a fixed rule can't. Set that up here; the next few slides build on it.

Block A · What is an agent?

When is the use of an agent appropriate?

The perceive → decide → act loop is worth the extra complexity only when "decide" needs real judgment. A quick gut check ↓

✗ Not an agent problem

The rule already exists — writing it down is the whole job.

  • Track a price on a page and alert if it drops below a number — a scheduled script + if/else
  • Rename ten thousand files to a fixed pattern
  • Pull an API every five minutes and log the response
  • Check that a CSV's columns match a fixed schema

✓ Good fit for an agent

The output depends on judgment a script can't cheaply encode.

  • Read a stack of PDFs and pull out the ones that actually match a research question
  • Triage support tickets by what the person actually means, not a keyword match
  • Draft a first-pass reply that references the right internal doc
  • Turn a messy meeting transcript into real action items

The price-tracker line is a real, deliberately boring example — resisting the temptation to reach for an LLM when a five-line script would do is one of the running themes of the day.

Block A · What is an agent?

Task, workflow, or agent?

Task One model call. Summarize this. Classify that.
Workflow Several model calls, chained through control flow you wrote — judgment at fixed points you decided.
Agent The model decides its own next steps at runtime — which tool to call, whether to retry, when to stop.

The system we built today is a workflow, not an agent.

Our code hardcodes the order — discover → scrape → summarize → decide → publish, every run. The model only fills in judgment; everything else is plain code. Same model, different code, and this could be a real agent instead.

Not a flaw — the right call. Anthropic recommends workflows for well-defined tasks like this one: predictable, cheap, errors don't compound. Full agentic autonomy is for genuinely open-ended problems.
Speaker note "Not building/training the LLM" is NOT why this is a workflow, not an agent — using a pre-trained model is normal either way. The real line: who decides what happens next. Here, our code picks the order, always the same. A real agent would have the model itself decide — e.g. which source to check next, or whether to retry a failed scrape — at runtime, not something we wrote in advance. Good moment for a provocation: "What would make this a real agent?"

Block A · The model

What you actually just talked to

ModelGemma 4, Google DeepMind — April 2026
This buildgemma4:e2b — the smaller of two on-device sizes (e2b / e4b)
"e2b" means2.3B effective parameters — not the whole story, see right
On disk~7 GB — more than 2.3B params' worth, because of how it's built
Context window128K tokens available; this project caps it at 8K — plenty for one article
Modalitytext, image, audio, video — we only ever send it text
Made concrete

2.3 billion parameters is enough that just writing them out as plain numbers, one per line, would fill roughly 40,000 novels. The 7 GB on disk is about the size of 2,000 photos on your phone. And the unused 128K context window is roughly a whole novel's worth of text in one go — this project only ever fills about 6% of it, one article at a time.

“Effective” parameters aren’t the whole file. Gemma 4’s small models use Per-Layer Embeddings — a lookup table bolted onto every layer, cheap to store, cheap to query, not part of the “active” compute spent per token. It’s what lets a file this size run this well on a laptop CPU.

And “thinking”? Gemma 4 also has an optional extended-reasoning mode — put a <|think|> token in the prompt and it writes out a chain of thought before answering.

Speaker note Point back at the terminal from the last two slides — that's this model. If someone asks why it doesn't "show its work" like a reasoning model would: that's the <|think|> token being deliberately left out, not a limitation of the model itself.

Block B · Why local?

Three reasons

Privacy

Nothing you read or write leaves your laptop. No third party sees your interests, your sources, or your drafts.

Cost

Free after setup. No per-token bill, no quota, no surprise invoice for a batch job that ran long.

Offline

Works on a plane. Works when the venue wifi doesn't. The model is a file on disk, not a service you call.

Block B · Why local?

Small local models are weaker than the giant cloud ones.

That's not a footnote — it's useful. The constraint forces habits that sloppy prompting against a huge model lets you skip:

clear prompts structured output knowing when not to use the model

Hands-on · You vs. Gemma

Judge five articles, then check Gemma's homework

Groups of five. Same prompt, same five articles — everyone judges by hand first, then runs it through Gemma and sees where they agree.

Reader's interest

I want practical, evidence-backed articles about focus, attention, and deep work — things a busy person could actually try this week. Prefer real research or genuine lived experience behind the claims, concrete techniques over vague advice.

Reject generic productivity-app marketing and listicles, opinion pieces with no real evidence or experience behind them, and anything not actually about focus or attention.

Whole room · ~40 minutes
  1. 1Alone, 15 min — read the prompt, then all five articles on the next slide. Mark each approve or reject, privately.
  2. 2Groups of five, 10 min — compare calls, argue the disagreements, agree on one verdict per article.
  3. 3Run the same prompt and articles through Gemma, 10 min.
  4. 4Whole room, 5 min — where did you agree with the model? Where didn't you?

Facilitator only — what Gemma actually said

A — approve. “The article presents empirical research on the impact of technology on attention spans.”

B — approve. “The article directly addresses developing sustained focus through a trainable process.” Borderline on evidence quality — did every group agree?

C — approve. “The article provides concrete, actionable systems for improving focus and productivity.” Borderline on authenticity — the summarizer never sees the affiliate links and course pitch a human reader would. Would you have approved it after reading the whole page?

D — reject. “The article discusses the history of citizen science rather than focus, attention, or deep work.” Clean, correct, no ambiguity.

E — reject. “The article focuses on general habit formation rather than specific, evidence-backed techniques for focus or deep work.” Borderline on topic fit — real research, well-argued, but is habit/willpower close enough to count? The one most likely to split the room.

Hands-on · Your own run

Now break it on purpose

10:45 – 11:30 · Run end-to-end
  1. 1Run your own build, start to finish — your prompt (the one you just tuned, or your own from scratch), your sources, for real.
  2. 2Then break it on purpose: loosen the prompt until junk gets through, or tighten it until nothing survives.
  3. 3Watch which articles flip, and why — that's the model's judgment changing, not a bug.
11:30 – 11:45 · Read & compare
  1. 4Open the result — Calibre, an e-reader, or just your phone. See it in the format it was built for.
  2. 5Regroup and compare what each track built: what did your prompt keep that a neighbor's rejected?
Speaker note The point of "break it on purpose" is to make the model's judgment visible and adjustable, not mysterious — a looser or stricter prompt is a design choice you made, not a bug you introduced. This is also the moment to let people who are stuck ask for help before the final discussion.
